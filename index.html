Step 1: Scene Detection

Analyze video frame by frame

TransNetV2
  • Import a full-length video file — the system analyzes every frame to detect scene boundaries and shot transitions
  • Primary method: TransNetV2 deep learning model trained on dramatic shot changes for high accuracy
  • Fallback: PySceneDetect using content-based detection with Laplacian variance (works without TensorFlow)
  • Video metadata extracted via FFprobe — resolution, duration, frame rate, codec information
Configurable Detection method Gap frame tolerance (0–10)
Tech Stack
TensorFlow TransNetV2 PySceneDetect FFprobe Python

Step 2: Clip Extraction

Split, trim & deduplicate

Hash-based dedup
  • Video is split at each detected scene boundary into individual numbered clips using FFmpeg stream copy (no re-encoding, instant)
  • Clips shorter than the minimum duration threshold are automatically discarded — removes single-frame transitions and black screens
  • Optional trim of the first 0–2 seconds per clip to remove residual black frames from scene transitions
  • Fast deduplication: compares first + last 64KB MD5 hash of each file to eliminate near-identical clips without full file comparison
Configurable Trim start (0–2s) Min duration (1–10s) Workers (1–8) Gap frames (0–10) Delete original
Tech Stack
FFmpeg Python multiprocessing MD5 hashing Stream copy

Step 3: Smart Cropping

9-method crop detection

9 methods
  • Each clip is analyzed using 9 independent detection methods to find the optimal crop region for the target aspect ratio
  • Methods include: blur boundary detection (Laplacian variance), gradient variance, edge detection, symmetry analysis, center-weight scoring, and multi-frame sampling (3 frames per clip)
  • A weighted voting system combines all 9 methods to produce the final crop — logo regions are filtered out via connected component analysis
  • Results are cached with version management — re-processing only occurs when the detection algorithm is updated
Configurable 9:16 portrait (TikTok/Reels) 16:9 landscape (YouTube) Cache invalidation
Tech Stack
OpenCV Laplacian variance Gradient analysis Edge detection NumPy

Step 4: Video Compilation

Assemble into finished videos

Multi-format
  • Individual clips are randomly selected and assembled into finished videos — each clip is used only once across all compilations
  • Short-form (9:16, 20–90s): Vertical videos for TikTok, Instagram Reels, and YouTube Shorts with intelligent cropping applied
  • Long-form (16:9, 1–10 min): Landscape videos for YouTube's main platform — preserves original quality up to 4K
  • Capacity analysis calculates realistic output before processing — prevents oversized compilations and recommends optimal settings
Configurable Number of short videos Number of long videos Target duration per format Output directory

FFmpeg Capacity analysis Random selection Timestamp management

03
Master's Thesis — Data Science

Automated Risk Analysis of Municipal Invoices

Gothenburg City · 2021–2024 · Industrial Engineering, Mid Sweden University · 15 ECTS

5.4 M Transactions
18,774 Suppliers
97% FP Reduction
107.6 B Analyzed (SEK)

Step 1: Data Collection

5.4M transactions

5,433,668 rows
  • 48 monthly CSV files fetched manually from Gothenburg City's open data portal (2021–2024)
  • Encoding issues (UTF-8 vs ISO-8859-1) identified and standardized in the pipeline
  • Amount fields with text formatting (spaces as thousand separators) converted to float
  • 5,433,668 transactions combined into a single dataset — no rows excluded
Tools & Techniques
Python Pandas NumPy CSV Parsing Encoding data.goteborg.se

Step 2: System Design

7 modules

Modular Architecture
  • Architecture: 3 statistical core modules + 4 support modules designed iteratively
  • Module 1: Org. numbers validated via Luhn algorithm — 4.7% (882) lacked valid numbers
  • Modules 2–3: Transaction pattern analysis with 6 sub-analyses + CV-centered supplier profiling
  • Risk score 0–100 with combination bonuses (e.g. ×1.5 at threshold + disappearing) and legitimacy deductions
Tools & Techniques
Python 3.9+ Design Science Research Luhn Algorithm Openpyxl Jinja2

Step 3: Iterative Development

V1.0 → V4.3 (9 versions)

97% reduction
  • 9 versions iterated with systematic measurement of high-risk suppliers per version
  • Breakthrough V4.3: CV (coefficient of variation = σ/μ) strongest single indicator — uniform amounts flagged
  • LOV suppliers (standardized care rates) caused 50% of false positives → −15 point adjustment
  • Result: 1,516 → 31 high-risk suppliers (−97%) — but all top 10 verified as false positives
Tools & Techniques
CV Analysis (σ/μ) Benford's Law + Chi² Z-Score LOV Detection Volume Normalization

Step 4: Semantic Analysis

Module 5

16 associations flagged
  • Filtered non-profit associations (802-org.nr) that invoiced services rather than received grants
  • Flagged illogical combinations: sports club → "Administrative services" to education department
  • 16 associations identified, totaling 13.2 MSEK to the Labour Market and Adult Education Committee
  • Manual web verification per candidate: website, allabolag.se, IVO registry, Google search
Tools & Techniques
Python Filtering Text Analysis Regex Matching Allabolag.se IVO Registry

Step 5: External Verification

Freedom of Information

221 pages
  • 14 freedom of information requests sent to Gothenburg City, the District Court, and law firm dNovo
  • Meeting with Gothenburg City Leasing AB (3 representatives): confirmed attestation data not shared with Inyett
  • 221 pages of documentation received: contracts, invoice copies, attestation screenshots, audit reports, bankruptcy filings
  • Inyett (240+ municipalities) lacks CV analysis, semantic checks, and attestation flow analysis — confirmed 2026-02-20
Tools & Techniques
Freedom of Information Act Bolagsverket Gothenburg District Court Kronofogden Inyett / Visma

Step 6: Findings & Control Failures

Bergsjön Sportklubb

13 control failures
  • Bergsjön SK: 6 contract breaches, no bookkeeping, bankruptcy with 0 SEK assets despite 2.16 MSEK in municipal funding
  • Broken functional separation: attestation handler made exception decisions AND sat in the approval chain
  • 13 control failures independently confirmed by the administration's own PwC investigation (Report 59-2023)
  • Key insight: The statistical system did NOT flag this case — only semantic analysis found it
Tools & Techniques
COSO Framework Fraud Triangle (Cressey 1953) Fraud Diamond (Wolfe & Hermanson 2004) PwC Report 59-2023
Key insight: Statistical anomalies in municipal invoices correlate more strongly with legitimate business patterns (framework agreements, LOV care) than with irregularities. Semantic analysis combined with freedom of information requests proved to be the most powerful tools for uncovering control failures.
